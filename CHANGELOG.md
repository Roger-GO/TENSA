# Changelog

All notable changes to TENSA are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/), and the project adheres to semantic versioning once 1.0 lands.

## [Unreleased]

### Added
- `tensa --version` prints the tensa and ANDES versions.
- CI now runs the server tests on Linux, macOS (Apple silicon), and Windows with Python 3.12 and 3.13, and on pushes to `improve/**` and manual dispatch as well as `main` and pull requests. Linux runs the whole unit and integration suite; macOS and Windows run the unit tests plus a smoke test (`pytest -m smoke`) that starts a real `tensa serve`, lets it spawn a worker, loads IEEE 14, runs a power flow and a short time-domain simulation, and closes the session. Lint, types, and the GUI-parity check run once in their own job. Pip and ANDES's generated code (`~/.andes/pycode`) are cached, and `web/dist` is built once and shared between the jobs. `scripts/ci-matrix.sh` takes a stage (`lint`, `unit`, `smoke`, `full`, `acceptance`, or `all`, which leaves out the slow `acceptance` stage) so the same commands run locally.
- Coverage reports for both halves. `pytest --cov` measures the server, worker processes included (`pytest-cov` and `coverage>=7.10` are in the `dev` extra), and `pnpm test:coverage` measures the web UI (`@vitest/coverage-v8`). CI prints the server table in the job summary and uploads the HTML and XML (server) and HTML and lcov (web) reports as build artifacts. No external service is involved.
- `.gitattributes` keeps text files LF in every checkout, so a Windows checkout with `core.autocrlf` no longer turns sources into CRLF and fails `pnpm format:check`, and marks images, video, and archives as binary. Nothing in the repository changes, since every tracked text file was already LF.
- Ruff now flags any `open()`, `read_text()`, or `write_text()` in the server source and tests without an explicit `encoding=` (rule `PLW1514`), so the platform default cannot creep back in there. Ruff is capped below 0.17 in the `dev` extra, because that rule is still a preview rule and preview mode can change between releases.
- Agent-evaluation example: a PowerAgentBench-SS-style budgeted N-2 screening study on IEEE 39-bus (`examples/contingency_screening/`) with an exhaustive API-computed oracle, scripted baselines, an audited LLM-agent run, and scoring. Line elements now accept edits to the connection-status parameter `u`, so contingency studies can outage a branch through the API or inspector.
- Weekly dependency updates and a security audit. `.github/dependabot.yml` proposes updates for the server's Python dependencies, the web UI's npm packages, and the workflows' actions, and leaves ANDES minor and major releases out on purpose (they need the walkthrough re-run by hand). A new `audit` workflow runs `pip-audit` on a fresh install of the server with its `mcp` extra, and `pnpm audit --prod` on the web lockfile, every Monday and whenever a dependency file changes. Both only report for now: a finding fails the audit step and shows its table in the log, but not the workflow.
- The `acceptance` job in `server.yml` now runs the acceptance tests (the curl walkthrough, streaming TDS, abort, the OpenAPI descriptions, `warm-cache`) on Linux through `scripts/ci-matrix.sh acceptance`, a new stage that is also the command to run them locally. Until now the job was a placeholder that only echoed, so none of them ran in CI. The job no longer waits for lint and the test matrix, and the release workflow waits for it like for the other server jobs.
- A Playwright end-to-end job in `web.yml`. It builds the UI, starts `tensa serve` on a fresh workspace, and runs the flagship test (rewritten under Fixed below), which opens IEEE 14 in a real browser, runs a power flow, and checks the single-line diagram overlay and the Buses table against the live server. `web.yml` now also runs on changes under `server/`, because the job exercises the server, and the release workflow waits for it.
- Tests that pin `Content-Type: application/json` on every JSON body sent by the callers outside the web client: `examples/tensa_client.py`, the MCP server, and the curl walkthrough in `examples/`, plus the bundle export request in the web UI, which bypasses the shared client. Removing the header from any of them now fails a test instead of showing up as a 422 from a real server.

### Changed
- Python 3.13 is now a declared and tested version (trove classifier added, covered by the CI matrix).
- `vitest` and `@vitest/ui` moved from 3.2.4 to 3.2.7, because the new coverage provider has to match the test runner's version.
- Snapshot names and save-as names are now checked by one shared rule on the server, and the Save snapshot and Save as custom case dialogs apply the same reserved-name and trailing-dot checks as you type, instead of waiting for the server to answer 422.
- The release workflow (`.github/workflows/publish.yml`) is stricter. It runs the server and web test workflows first and uploads nothing unless both pass. It builds the sdist and then the wheel from that sdist, so the wheel that ships is the one a source install gets. It refuses a release whose git tag is not the package version (`v0.5.0` for 0.5.0, compared as PEP 440, and it must run on a tag), checks both archives with `scripts/check_dist.py` (same version, UI bundled, no source maps, license included, sdist rebuildable) and the metadata with `twine check`, installs the wheel into a clean virtualenv and runs `tensa --help`, `tensa --version`, and a lookup of the bundled `index.html`, and then uploads exactly those files from a separate job, the only one allowed to request a PyPI token. `server.yml` and `web.yml` can now be called from other workflows.
- The PyPI classifier is now `Development Status :: 4 - Beta` (it was Pre-Alpha).
- The `dev` extra now includes `hatchling` and `editables`, which the packaging tests use to run the real build backend.
- FastAPI is now allowed from 0.133 up to (not including) 0.143, where it was pinned to 0.119.x, and Starlette is declared directly as `>=1.3.1,<2`. The old pin held Starlette below 0.49, and every Starlette release before 1.3.1 has a published advisory. Several apply to what this app does, because it serves the UI through `StaticFiles` and accepts uploads: a quadratic-time `Range` header in `FileResponse` (fixed in 0.49.1), a UNC path in `StaticFiles` on Windows that makes the server authenticate to a remote host over SMB (1.1.0), and urlencoded form limits that were not enforced (1.3.1). A new install now resolves to FastAPI 0.142 and Starlette 1.7. The server suite passes at both ends of the range, FastAPI 0.133.0 with Starlette 1.3.1 and FastAPI 0.142.2 with Starlette 1.7.0. `python-multipart` is now `>=0.0.31`, the first release past its published advisories (denial of service in the multipart and urlencoded parsers). FastAPI 0.133 and later also require `Content-Type: application/json` on a request with a JSON body: a body sent with no `Content-Type` header is no longer parsed as JSON and answers 422, where 0.119 accepted it. The web UI, the MCP server, and `examples/tensa_client.py` already send the header, so only hand-written scripts that leave it out need a change (`curl` needs `-H 'Content-Type: application/json'` with `-d`).
- The server tests that read repository files (`pyproject.toml`, the workflows, `scripts/`, the web package files) share one helper module, `server/tests/_repo.py`, for the repository paths and for loading a script as a module, where each file used to repeat them. Ruff's import sorting treats `tests` as first party for that import.
- The web tests for the dialogs that close themselves share one fake-clock helper (`web/tests/unit/helpers/beatClock.ts`), where four test files each defined their own.
- `server/README.md` is the long description PyPI shows for the package, and it read like a contributor page. It now opens with `pip install tensa`, how to run the server and the MCP server, the `tensa serve` flags, the Content-Type rule for JSON bodies, and the trust model, with the development setup and test commands under a Development heading at the end. Its links are absolute, since PyPI does not resolve relative ones, and a test keeps it that way.
- The web workflow is named `web` instead of `web (v0.1+ UI)`, so its checks appear as `web / <job>`. A branch protection rule that lists them by the old name needs the new one.
- `llms.txt` lists the `Content-Type: application/json` requirement among its gotchas, so an agent that builds requests by hand sees it before it gets a 422.
- `tailwindcss` and `@tailwindcss/vite` are required as `^4.2.4` instead of `^4.0.0-beta.7`, which still admitted a beta. The lockfile already held 4.2.4, so the built UI does not change.
- `engines.pnpm` in `web/package.json` now says `>=11` (it said `>=9`), matching `packageManager` and the contributor docs. The esbuild build permission was listed twice, as `pnpm.onlyBuiltDependencies` in `web/package.json` and as `allowBuilds` in `web/pnpm-workspace.yaml`. pnpm 11 reads only the second, so the first is gone.
- `mypy` treats `pyarrow` as untyped, like ANDES and openpyxl, because it ships no type information. A clean install of the `dev` extra now type-checks with no errors, and the one `type: ignore` that only held with a typed pyarrow is gone.
- In the CI matrix the smoke test on macOS and Windows now runs even when that leg's unit tests fail. It used to be skipped then, which hid whether the real server, worker, and simulation path works on that system, the thing a failing leg most needs to know.
- Live time-domain streaming is much cheaper on large cases. A frame used to be an Arrow table with one column per variable, so every frame repeated all the column names and described every column, and the browser looked each column up by name. On the 1209-column WECC case that was a 134 KB frame for 9.7 KB of values, 9.4 ms to encode and 11 ms to decode. The names now go out once, in `stream_start` (`metadata.var_columns`, as before), and each frame holds only `t` and one `v` list column with the row's values in that order: 10 KB, 0.1 ms to encode and 0.2 ms to decode on WECC, with the browser matching values to names by position. Frames are still Arrow IPC, so any Arrow reader opens them, but a client that read columns by name from each frame must now take the names from `stream_start`; `tensa.core.stream.decode_batch` is the reference reader, and `stream_start.metadata.schema_version` is now `2.0`. `numpy`, which ANDES already requires, is now declared as a direct dependency of the server.
- The time-series plot no longer destroys and rebuilds its charts on every streamed frame. Each frame produced a fresh description of every chart, and the plot read a fresh description as a different chart, so during a live run each stacked chart was torn down and created again at the frame rate (two groups at 30 frames per second meant about 60 chart builds a second). A chart is now created once and fed each frame in place, and is rebuilt only when what it shows changes: the variables selected in its group, the theme, a run's colour, or the set of overlaid runs. The in-place update re-ranges both axes, so the time axis still grows with the data.
- The single-line diagram's layout engine (ELK) no longer runs on the UI thread, and no longer runs more often than it has to. ELK is 1.4 MB of what used to be a 2.76 MB main script, so every visit downloaded and parsed it, and every layout froze the page while it ran. On the 179-bus WECC case, opening the case kept the main thread busy for 1.7 s in one measured run (longest stretch 0.83 s). The engine is now its own file (`assets/elk-worker.min-*.js`), fetched the first time a layout is needed and run in a Web Worker. The main script is 1.3 MB, the same load keeps the main thread busy for 0.5 s (longest stretch 0.29 s), and the diagram it draws is identical. A layout also used to start every time the topology was fetched again, which happens after each power-flow run, reload and parameter edit. It now starts only when a bus or the terminals of a branch change, and not at all when the saved layout already places every bus: a case you have arranged by hand, or IEEE 14 and 39 by file name, which have a built-in layout. If the worker cannot start (a blocked script, or a content security policy that forbids workers), the diagram falls back to the grid layout it already used when ELK failed, instead of waiting forever.

### Fixed
- Documentation that no longer matched the program. `server/README.md` listed a `--worker-rss-limit-mb` flag that does not exist and gave a wrong `--max-sessions` default (the default is 4, not a CPU-based formula); it now lists exactly the flags `tensa serve` accepts, `--allow-origin` and `--reload` included, with their real defaults, and a unit test compares the list with the command. The development-mode command in the README and `CONTRIBUTING.md` now passes `--allow-origin http://127.0.0.1:5173`: without it the Vite dev server's requests were answered 400. The README's From source steps, the development and demo commands, and `CONTRIBUTING.md` now have PowerShell equivalents for everything that only worked in a POSIX shell (venv activation, `&&` chains, `VAR=value command`, backslash continuation), and say that Windows on ARM is not supported, because `kvxopt` and `pyarrow` publish no wheels for it. `web/README.md` still described the token login that was removed and linked to plan files that are not in the repository; it now matches the app.
- Text in the API schema that described features as still to come or no longer true. The "run a time-domain simulation" summary said streaming was still to come and the request schema named a `?stream=ws` parameter that never existed (streaming is the `WS /api/ws/{session_id}` channel). The add-element `model` description listed nine models where the form offers many more, the save-case description said `.raw` is not supported although the built-in PSS/E v33 writer produces it, and the power-flow `run_id` description pointed to `GET /sessions/{id}/pflow/{run_id}`, which does not exist (`GET /sessions/{id}/operating-point` re-reads the solved state). Several "v0.1" and "Phase A" qualifiers are gone, and `web/src/api/generated.ts` and the GUI-parity ledger follow. A unit test now fails on promise-about-the-future wording in the schema and on a description that names a route that does not exist.
- Stale planning notes in places users and contributors read: the package description in `web/package.json` ("v0.1 UI"), the trust-model docstring and the Windows startup warning (which told users to wait for enforcement "in a future plan"), the module notes of the session manager, job registry and report code, a note in `web.yml` about a publish workflow that now exists, and comments in the web stores and the Save system dialog that still mentioned the auth token or said `.raw` could not be written.
- The Playwright specs depended on the auth-token login that was removed from the app, so every one of them was skipped with `test.fixme` and none ever ran. The flagship spec (`web/tests/e2e/load-pf-flow.spec.ts`, the one the end-to-end job under Added runs) is rewritten for the current UI and no longer needs a token. The other four files (seven tests) stay skipped, with a note that their selectors predate the current layout. The comments in `web/playwright.config.ts` now describe how the tests run: against the build the substrate serves, or against the Vite dev server with `tensa serve --allow-origin http://127.0.0.1:5173`.
- The dialogs that close themselves a moment after a success left that timer running after the dialog went away: Import bundle and Export bundle (800 ms), Save snapshot (600 ms), Load snapshot (1200 ms), Save system (1200 ms), and Save as custom case (600 ms). Closing a dialog by hand inside that window and opening it again let the old timer close the new dialog, and a test run that finished inside the window hit an unhandled error after teardown. Dismissing the dialog with Escape while its request was still running did the same once the answer arrived. The timers are now cancelled when the dialog closes, and none starts after it has. The three-second confirmation on the Load snapshot Delete button follows the same rule. The Save system modal belongs to a button that stays on screen, so it cancels its pending close whenever the modal opens or closes, and a save that answers after the modal was dismissed still writes the layout file but no longer touches the modal that is open now.
- `tensa serve` with the default OS-assigned port (`--port 0`) rejected the web UI's own requests with `400 bad-origin`: the Host/Origin allow-list was built from port 0 before the real port existed, so the browser's `Origin: http://127.0.0.1:<port>` never matched. The server now binds its listening socket first, builds the allow-list from the real port, and serves on that same socket, so the printed URL always works. `--open` now works with any port, including the default (it used to refuse port 0), and `--reload` with port 0 picks a free port up front. On Windows the socket asks for exclusive use of the port instead of `SO_REUSEADDR`, which there lets another process share it.
- The time-domain step size `h` was silently ignored: it was written to `TDS.config.h`, which ANDES never reads, so every run used the 1/30 s default. `h` now sets `TDS.config.tstep`, and the trapezoidal integrator steps at exactly the requested size in batch runs, streaming runs, and sweeps. The TDS report now shows the step actually used. The QNDF integrator still chooses its own step (ANDES ignores `tstep` there), so bound it with `max_step`. The API and UI wording for `h` now says so and no longer claims a 1/120 s default.
- Workspace path handling on macOS: the lookup that canonicalizes case files called libc's variadic `fcntl` through ctypes without a prototype, which passes the buffer where the callee does not look on Apple Silicon, so loading a case could fail there. It now uses the standard-library `fcntl`. The workspace root and the parent folders of files written back (layout sidecars, saves) are canonicalized the same way, so `--workspace ~/Cases` on a folder stored as `~/cases`, or with a different Unicode normalization, no longer rejects every load as outside the workspace.
- Workspace paths that cannot be resolved now return a 4xx instead of a 500: permission denied on a parent folder (layout read/write), and on Windows a missing file or an invalid file name (`WinError 123`) when loading a case.
- Saving the single-line-diagram layout returned a 500 on Windows with Python 3.12: `os.fchmod` does not exist there before Python 3.13, and the missing attribute was not the `OSError` the code expected. The call is now skipped where the platform lacks it and the file mode is still applied after the write.
- File names that Windows reads as something else are now refused on every platform, so a workspace, bundle, or snapshot made on Linux or macOS still works once it reaches Windows. Refused: DOS device names (`CON`, `nul.txt`, `COM0` to `COM9` and `LPT0` to `LPT9` including their superscript forms, `CONIN$`, `CONOUT$`, any extension or case), `:` (a drive prefix or an NTFS alternate data stream), a trailing dot or space, control characters, and the other characters Windows cannot store. This applies to every case file inside an imported bundle (which also checks all destinations before writing any), to snapshot names, to save-as names, to the file name given to Save system, and to the layout of a case file that is not in the workspace yet. A layout for a case file that is already there is saved whatever the file is called, so a case such as `case_12:30.raw` keeps its single-line-diagram layout on Linux and macOS. Snapshots saved under a name that is now refused still appear in the list and can be restored and deleted; only new saves are held to the rule. Invalid bundle entries answer 422, and the snapshot name check now also rejects a trailing newline that the old pattern let through.
- Bundle import and Save system no longer write through a symlink in the workspace. A link whose target does not exist yet slipped past the check, and the write then created the file wherever the link pointed, outside the workspace if it pointed there. Such a link is now refused before anything is written.
- The reported version was wrong: `tensa.__version__` was hard-coded to `0.1.0.dev0` while the package is 0.4.0, so the OpenAPI `info.version` and the `tensa_version` stamped into exported bundles and saved snapshots named a version that never existed. It is now read from the installed package metadata, so `server/pyproject.toml` is the only place it is set, and `web/package.json` (which said 0.0.1) now matches. Run from a source tree where tensa is not installed, it reports `0+unknown`. After bumping the version, reinstall an editable checkout (`pip install -e ./server`) so the metadata catches up; a unit test fails until you do, and also fails if `web/package.json` or `CITATION.cff` drift from `pyproject.toml`.
- Saving a case as PSS/E `.raw` no longer depends on the platform's default text encoding. On Windows the file was written in the ANSI code page (cp1252) with CRLF line endings, and a bus name that code page cannot hold made the save fail. It is now always UTF-8 with LF line endings. ANDES sniffs a `.raw` file's encoding with chardet rather than assuming one, and before chardet 6 it mistook a UTF-8 file whose only non-ASCII text is one accented letter for Latin-1 or MacRoman and read the bus name back garbled, so TENSA now requires `chardet>=6`.
- Editing a controller parameter in a PSS/E `.dyr` clone no longer fails on, or rewrites, files saved the way PSS/E saves them. A `.dyr` in the Windows code page (an accented plant name in a comment) was rejected as invalid UTF-8, and every edit converted the file's line endings. The edit now changes only the one number and leaves every other byte alone, including a UTF-8 byte-order mark. Text after a record's `/` is now treated as a comment, as ANDES does, so a trailing comment no longer made the next record impossible to find.
- Ctrl+C in the terminal running `tensa serve` no longer prints a `KeyboardInterrupt` traceback from every worker. A terminal sends SIGINT to the whole foreground process group, so each worker raised out of its command loop and died on its own; workers now ignore SIGINT and the server stops them in its own shutdown. (A Ctrl+C in the first seconds after a session starts, while its worker is still importing numpy and ANDES, is not covered.)
- Each worker now limits its numerical libraries to 4 threads by default (`OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS`, `VECLIB_MAXIMUM_THREADS`, `NUMEXPR_NUM_THREADS`). Before, every worker started one BLAS thread per core, so a few sessions on a many-core machine fought over the cores. A variable you have already set is left alone. OpenBLAS, MKL and numexpr use `OMP_NUM_THREADS` when their own variable is unset, so if you set `OMP_NUM_THREADS` (to 1, say, or to 8) the variables you did not set take that count instead of 4, and `GOTO_NUM_THREADS` is likewise left to OpenBLAS. `TENSA_WORKER_THREADS=N` sets all five to `N` whatever else is set. The values are put in the environment as the worker starts, because numpy reads them while it loads.
- On Windows, workers now die with the server. Linux and macOS workers already exited when their parent did, but Windows has no equivalent, so a killed server left its workers running. Each worker is now placed in a Job Object that Windows closes, workers included, when the server process ends. If the Job Object cannot be set up, a warning is logged and the session starts normally.
- A server that was killed (SIGKILL, a crash, power loss) no longer leaves its clone-on-write scratch folders in `<workspace>/.sessions/` forever. Each folder now records which server process owns it (its process id, the host and container it runs in, and when it started), and the next `tensa serve` on that workspace removes folders whose owner is gone, or whose process id now belongs to a different process, as happens when a container restarts or Windows reuses the number. A folder with no record, or one recorded by a server on another host or in another container, whose process id means nothing here, is removed only when it has not been touched for 24 hours. A folder belonging to a server that is still running on the same host is never touched. Closing a session on Windows also now deletes a clone of a read-only case file, which the folder cleanup used to fail on and skip silently.
- The warning for case files that read outside the workspace compared paths with a plain string prefix, so a sibling folder such as `cases2` counted as inside a workspace named `cases`, and it recognized Python's own files with a Linux-only path pattern. It now compares whole path components (ignoring letter case where the platform does) and finds the interpreter's own files from the interpreter's prefixes and site directories, so it also works with Homebrew, conda, and Windows installs.
- A trapezoidal run after a QNDF run on the same session ignored the requested step size `h` and kept taking QNDF-sized steps. QNDF leaves ANDES's fixed-step switch (`fixt`) at 0 on the System's configuration, and ANDES keeps the QNDF integrator object when a run resumes. Each run now sets `fixt` for the integrator it asked for (an explicit `fixt` override still wins) and replaces a leftover QNDF integrator with the trapezoidal one. The reverse switch is not possible after a run, because QNDF needs history that only ANDES's initialization builds, so asking for QNDF on a session that already ran trapezoidally now answers 422 and asks for a reload, instead of quietly running trapezoidal.
- A step size `h` that is zero, negative, NaN, or infinite is now refused wherever it enters. ANDES accepts such a value and quietly makes the rest of the session variable-step. `POST /tds` already rejected `h <= 0` but let `Infinity` through, the sweep request had no check, and a WebSocket `start_tds` frame passed the value on unchecked, so a non-numeric `h`, or an integer too large to be a float, raised unhandled. All of them now answer 422 (REST) or an error frame (WebSocket) before a worker is involved, and a sweep fails once instead of recording an error for every iteration.
- A streamed time-domain run announced the wrong step mode and refused too late. Its `stream_start` frame reported fixed or variable step from the session's leftover `fixt` setting, which the run had not set yet, so a first QNDF stream, or a trapezoidal stream after a QNDF run, carried the wrong `fixed_step` and the wrong decimation algorithm (`boxcar-mean` versus `boxcar-mean-best-effort`). It now follows the requested integrator and any `fixt` or `tstep` override. A run the server refuses, QNDF on a session that already ran trapezoidally or an unknown `tds_config_overrides` key, is now refused before the stream starts, so the client gets the error and no start frame, and the session's configuration is left as it was. The `POST /tds` 422 for such a refusal now ends with one hint to reload instead of three.
- A layout path that runs through a file, such as `case_path=ieee14.raw/x.raw`, answered 500 on Linux and Windows (macOS already answered 400). Anything that is not a directory is now rejected with a 400.
- Exporting a bundle no longer writes case files that import would refuse. A workspace file such as `con.raw`, `case_12:30.raw`, or `.hidden.raw` loads on Linux and macOS, but the bundle holding it failed import everywhere, and an edited case named `con.raw` exported as `con.xlsx`. Export now answers 422 with the name of the file and asks for a rename, and also answers 422 when the case has more than 16 case files, the most an import accepts.
- On Windows, restoring or deleting a snapshot whose name Windows reads as a device (`aux`, `con.v2`) is now refused like a new save. Such a snapshot cannot exist there, so the exemption for older snapshots only reopened device-name access; Linux and macOS are unchanged. The layout exemption for existing case files and the snapshot exemption now follow the same platform rule, and on Windows the snapshot list no longer shows a name that restore and delete would refuse.
- The sdist could not be built into a wheel, so `python -m build` (which builds the wheel from the sdist) and any install from the sdist failed with `License file does not exist: ../LICENSE`. `server/pyproject.toml` read the license from `../LICENSE` and force-included `../web/dist`, and an unpacked sdist has neither. `server/LICENSE` is now a copy of the license (a test keeps the two identical), and a small build hook, `server/hatch_build.py`, replaces the `force-include` table. The sdist now carries the built UI as `src/tensa/static`, so a wheel built from it serves the UI too, and a build with no UI at all still fails with a message that says to run `pnpm build`, instead of producing a package that answers 404 at `/`. The hook also lets `pip install -e ./server` work before `pnpm build` has run, and it no longer leaves a copy of the UI in site-packages that the app never read and that went stale after the next UI build.
- The wheel shipped the UI's source maps, about 10 MB uncompressed that a browser only fetches when its developer tools are open. The wheel and the sdist now leave out every `*.map` file.
- `pip install 'tensa[mcp]'` installed version 2.x of the MCP SDK, and `tensa mcp` then exited with a message saying the extra was not installed. SDK 2.0 renamed `FastMCP`, which the server imports. The extra is now `mcp>=1.28.1,<2` (1.28.1 is the first release past its published advisories). `tensa mcp` was checked end to end against 1.28.1 and 1.30.0: it starts a private `tensa serve`, lists its tools, and answers a call. Moving to the 2.x name is a separate change.
- On Windows, two jobs updated back to back could not be told apart by time: the monotonic clock there ticks about every 16 ms, so equal `updated_at` values fell back to insertion order. The `409` that names the job holding a busy session could then name the wrong one, and the activity panel could order jobs wrongly. Job timestamps are now strictly increasing.
- When a failed job was merged into an earlier identical failure, the final update sent to the activity panel for the merged job still took its time from the raw monotonic clock, so on Windows it could tie with, or sort before, the update of the job it was merged into. It now uses the same strictly increasing clock as every other job update.
- `SessionManager.shutdown` now takes the sessions it closes out of the registry, as closing one session already did. It left them there, so each session's worker handle and abort event (five POSIX semaphores) lived as long as the manager, and a manager kept alive by a reference cycle (an app object in a test, for one) let the cycle collector free them at an arbitrary moment. When that moment fell inside the start-up of Python's multiprocessing resource tracker, the full test run printed `ResourceTracker called reentrantly ... might leak` warnings. No semaphore was lost, and the warnings no longer appear in the suite. Two integration tests that held the exception they provoked in a local, another reference cycle that kept a session's worker handles, no longer do.
- On Windows, the warning for case files that read outside the workspace logged a line for a path that contains a NUL byte, which no file can have and whose open fails anyway. POSIX already skipped it; the check no longer depends on the platform.
- The first test of the abort acceptance suite failed on a fresh CI runner with a read timeout. It loads IEEE 14 with httpx's default 5 s limit, and ANDES generates its Python code for the models on the first load on a machine, which takes longer. The acceptance helpers now allow that first load up to 180 s.
- The Save snapshot dialog test that fills the name field through the native setter no longer waits on a timer, and a new test covers a dialog that unmounts inside its auto-close beat. That case is what made the old test fail on a loaded CI runner, before the timer fix under the dialogs bullet above.
- Streamed frames that batched several steps carried the wrong times. ANDES hands the per-step hook one array for the time and updates it in place, and the stream kept that array instead of its value, so every row of a frame sent with `decimation: "none"` and a `max_rate_hz` had the time of the step that closed the window, and a boxcar-mean row was stamped with that step's time instead of the mean time of its window (up to a step late). The time is now copied when the row is buffered.
