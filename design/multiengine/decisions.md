# Decisions log: multi-engine project

Decisions taken without the user, with the reason, newest last. For review at the end.

| # | Date | Decision | Reason |
|---|---|---|---|
| 1 | 2026-11-20 | The ANDES wrapper stays as it is and becomes the ANDES engine; Sienna is a second implementation of the worker's op surface. | Inventory run 001: 25 of 38 engine-touching modules are ANDES-specific throughout, so a seam inside the wrapper would mean rewriting working code. |
| 2 | 2026-11-20 | Kimi workers only work from text they are given (source files, installed package source and docs, real command output). | In run 001 the file-grounded report I checked was accurate; the from-memory Sienna reports contradicted each other. |
| 3 | 2026-11-20 | Dev environments live in `%LOCALAPPDATA%\tensa-dev` (Python venv, portable Node 22, pnpm virtual store, Julia project). | Keeps tens of thousands of files out of OneDrive sync. |
| 4 | 2026-11-20 | Node installed as the portable zip from nodejs.org (SHA-256 checked against the published sums), version 22.23.5, not the winget MSI. | The MSI needs administrator rights, which this laptop does not grant. Node 22 is the major `.nvmrc` and CI name. |
| 5 | 2026-11-20 | Web dependencies installed with `pnpm install --frozen-lockfile --virtual-store-dir %LOCALAPPDATA%\tensa-dev\pnpm-vstore`. | A junction for `web/node_modules` failed under pnpm; moving only the virtual store leaves 43 link entries in OneDrive instead of the whole tree. Nothing committed changes. |
| 6 | 2026-11-20 | Julia installed through juliaup (winget `Julialang.Juliaup`), default channel `release` (1.13.4 at install). | User-scope install, no admin. If the Sienna packages do not resolve on this release, the LTS channel is added beside it. |
| 7 | 2026-11-20 | The Sienna reference pack for workers is the installed package source and its `docs/` folder under `~/.julia/packages`, not web pages. | Exact for the versions that resolved; no scraping. |
| 8 | 2026-11-20 | Bridge to Julia: `juliacall` embedded in the existing Python worker; a separate Julia process is the fallback. | Spike: a Python callback ran on every solver step and stopped the run on request; warm calls take milliseconds. Reuses pipes, abort, messages and session handling. |
| 9 | 2026-11-20 | More than one Julia environment is allowed for, and the adapter records the package versions it ran with. | PSID 0.16 and PowerSimulations 0.34 pin PowerFlows 0.16; the current PowerFlows is 0.25 and cannot share their environment. |
| 10 | 2026-11-20 | In comparison runs loads are constant impedance at the solved voltage in both engines unless the study says otherwise; in Sienna they are represented as `FixedAdmittance`. | ANDES does this by default; Sienna keeps constant power, and its power flow and dynamics packages read a ZIP load's impedance part differently. Without it the engines disagree on stability itself. |
| 11 | 2026-11-20 | Model fidelity has three states per engine and model: exact, known difference (with a documented entry), unsupported. A model an engine drops is always reported, never silent. | PowerSystems skipped `EXDC2` with a warning and gave the machine a fixed exciter; PSID failed on `IEEET1` after PowerSystems parsed it; `TGOV1` differs by a documented modelling choice. |
| 12 | 2026-11-20 | A write-run-fix worker loop may change only the file it owns, never input data or the check, and stops when an error class repeats. | The unattended loop deleted machines from the `.dyr` to get past a parser error. |
| 13 | 2026-11-20 | Server baseline on this PC is what CI runs on Windows: `pytest -m "not acceptance" tests/unit` and `pytest -m smoke tests/integration`. The full integration and acceptance suites run in GitHub CI on Linux. | The full suite hung on Windows (a worker test idle for 30 min); WSL is not installed and needs admin. |
| 15 | 2026-11-20 | An engine is a handler table chosen when the worker starts (`EngineRuntime`), not a class with the wrapper's methods. | The worker's handlers reach the ANDES `System` directly (`run_tds`, `run_pflow`, reports, save, bundle export), so a second engine cannot be slotted in under them; the existing handlers become the ANDES runtime untouched. Found by the spec review. |
| 16 | 2026-11-20 | Worker-written code is produced as several independent candidates, each applied and checked in its own git worktree; candidates are then run against each other on real inputs before one is taken. | Four identity readers agreed on every field of 22 case files, which their own tests could not show; for the key assignment only one of four resolved dynamic models on a real case. |
| 17 | 2026-11-20 | A worker may not edit a test it was not given. An existing test that pins a shape the unit changes on purpose (the worker's argument list, the session descriptor) is updated by the architect, with the reason in the commit. | Three candidates stopped at such a test and refused to touch it, which is the wanted behaviour. |
| 18 | 2026-11-20 | Before a push that changes the API, the acceptance tests that run on Windows are run locally (`test_openapi_descriptions`, `test_topology_alterable_params`, `test_abort`, `test_tds_streaming`). | CI's Linux acceptance job failed on the seam: every route must document a 4xx or be on the list of input-free routes, and `GET /engines` was on neither. |
| 19 | 2026-11-20 | Keys for ANDES lines are matched to the case file by bus pair and kind, not by position; what ANDES adds for a three-winding transformer gets `engine:andes:` keys and stays out of comparison. | ANDES keeps MATPOWER branch rows in file order and PSS/E branches with transformers last, so no single position rule holds; found by running the key assignment on thirteen shipped cases. |
| 20 | 2026-11-20 | A field added to an existing response is declared with a null default or a default factory, never with a literal default; the web API types are regenerated and type-checked in the same change as any schema change. | `has_dynamics: bool = False` made openapi-typescript emit the field as required, and the regenerated types broke 106 typed fixtures in the web tests. Caught locally before the push. |
| 21 | 2026-11-20 | Keys belong to one content of a case file: the same path with another size or modification time is keyed afresh. | A session that reloads a file replaced on disk would otherwise hand the old file's circuit and device ids to the new file's elements. |
| 22 | 2026-11-20 | Every two-terminal AC branch has the key `branch:<from>-<to>-<ckt>`; whether it is a line or a transformer is reported beside the key, not in it. | Engines classify the same record differently: `npcc.raw` has 27 transformer records, PowerSystems makes 96 transformers of it, ANDES makes 27 from the raw and 96 from the xlsx. Replaces the earlier decision to keep `line:` and `xfmr:`. |
| 23 | 2026-11-20 | Work is run as parallel tracks: the Sienna track (Phases 4 to 6) and the ANDES-gap track (Phase 7A) advance at the same time, and work that needs no local run (model audits, specification drafts, reading of package documentation) is fanned out to many worker calls at once. | The worker API allows 200 requests a minute and the laptop has 16 logical cores; one or two units in flight used neither. Set by the user. |
| 24 | 2026-11-20 | Three roles, by the user's instruction: worker models write code; an Opus 5.5 reviewer reads every candidate diff and makes whatever edits it needs; the architect checks only after the reviewer has passed it, and does not rewrite product code. | Keeps the most capable review on every change while the architect's time goes to design, verification by running, and choosing between candidates. |
| 25 | 2026-11-20 | The case file is the reference for what a system is. Where an engine's own reader departs from the file, its adapter puts the file's value back and reports the correction; it does not hide the difference and does not tune one engine to another. | Found by comparing what ANDES and Sienna hold for six PSS/E cases, element by element: PowerSystems uses the bus record's stored voltage as a generator's setpoint (the file gives the setpoint as `VS`), snaps a transformer's ratio to its tap-step grid (0.9 in `ieee39.raw` becomes 0.9143), and turns a branch record between two voltage levels into a transformer that keeps half the line charging (20 branches of `npcc.raw`). With those three put back, the power flows agree on all six cases; everything else was already identical. |
| 26 | 2026-11-20 | Agreement between candidates is evidence, not proof. A candidate set is also checked against something none of them wrote: the engine's own value for the same file, a hand-worked record, or the format's documentation read by the reviewer. | Three case-facts readers agreed on 22 files and all read a two-winding transformer's ratio as `WINDV1` alone, because the reference they were given (ANDES) does; the file's ratio is `WINDV1 / WINDV2`. They had also all inherited one reader's mistake about where a three-winding record ends. |
| 27 | 2026-11-20 | A transformer's ratio is the file's: `WINDV1 / WINDV2` for a two-winding record (with the nominal voltages for `CW` 3), not the first winding's value alone. Where the second winding's ratio is not 1 the adapter says so in a note, since ANDES reads `WINDV1` only and the two engines then hold different networks for a reason the user should see. | Follows from decision 25: the file is the reference, and ANDES is an engine like any other. No shipped case has a second-winding ratio other than 1, so the six fixture cases are unaffected. |
| 28 | 2026-11-21 | An element added during a session takes the smallest ordinal on its bus (or bus pair) that no element of the session holds; a switched shunt, which has no id in a PSS/E file, takes the first ordinal on its bus after the fixed shunts' ids. An element already keyed keeps its key. | The first workflow test built the cases: a fixed and a switched shunt on one bus, and a load added on a bus whose only load has id 2, were each handed a key another element held and got a `~2` suffix, which is not a key. Smallest-free is deterministic under a replay of the edit journal and is what a save and reload of the edited case mostly gives; a key names an element in one state of the case, so reuse after a delete is accepted. |
| 29 | 2026-11-21 | A unit's checks fail when any of its own tests is skipped or none ran, and a reviewer confirms each new test ran and fails under the break it is for. | The eigenvalue sweep candidate passed every check with all its integration tests skipped (they looked for case files that were not there) and code that raised on any real System. The review also found that ANDES's own `EIG.sweep` does not recompute after the first value, since `TDS.init()` returns at once when already initialised; each sweep point is therefore a System built and set up afresh. |
| 30 | 2026-11-21 | The Sienna adapter asks PowerSystems for the file's circuit ids (`branch_name_formatter`), never its default branch names, and the engines are held to each other at 2e-5 pu and 2e-5 rad on the power flow. | PowerSystems names parallel PSS/E branches by a running count in dictionary order, so two circuits of a bus pair could be swapped (Kundur 8-9 and 9-10, six pairs of WECC): every branch key and every correction would have landed on the wrong circuit. The tolerance is 2.4 times the worst agreement measured (WECC, where PowerNetworkMatrices keeps the admittance matrix in single precision) and 235 times below the smallest effect of a missing correction. |
| 31 | 2026-11-21 | A branch's rating is the file's. Where the file gives none, a Sienna session shows none, and no loading. | PowerSystems computes a rating for a branch whose record has 0 and the Julia module can only report what the System holds, so every branch of Kundur, WSCC 9, NPCC, WECC and MATPOWER case14 would have shown a rating the case does not have. A fifth place where the file is put back (decision 25), this one on the Python side since nothing in the solution depends on it. |
| 32 | 2026-11-21 | The embedded Julia runs with one thread, without Julia's signal handlers, offline, with nothing loaded from the user's default Julia environment, and is called only from the worker's main thread. What Julia prints while the module loads is captured on Julia's side. | PythonCall warns that a multi-threaded Julia without its signal handlers can crash, and Julia's handlers would take Ctrl+C and crash reporting away from the worker; a user's `JULIA_NUM_THREADS=auto` would otherwise decide. Julia writes to the process's file descriptors, which no Python redirect reaches, and redirecting the descriptors around the start silenced Julia for the rest of the process. |
| 33 | 2026-11-21 | Switching engine releases the session on the server first and changes nothing in the client until that has answered; then the engine is set and the session cleared in one store update and the case is closed the way Change case closes it. A case opened under one engine is never reopened or replayed into a session of another. | The first candidate set the new engine before the old session was gone, relied on the order of two callbacks to keep it, and after a refusal left the user with no session. An edit journal of one engine's session replayed into another's would apply edits to a different model of the case. |
| 14 | 2026-11-20 | The branch's own workflow files get `multiengine` added to their push triggers, so every push runs the Linux CI; removed before the final pull request. | Server and web workflows only run on pushes to `main`, `improve/**`, `feat/**`. The only Linux test machine available is CI. |
