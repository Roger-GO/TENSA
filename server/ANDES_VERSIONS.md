# ANDES_VERSIONS.md

Phase A pins ANDES to `>=2.0,<3.0`. The substrate depends on **fourteen API contracts** that ANDES does not formally declare as public API — they are documented here so that an ANDES upgrade can be reviewed against this matrix before it lands.

## The fourteen API contracts

| # | Contract | Where the substrate uses it | Failure mode if it changes |
|---|---|---|---|
| 1 | `andes.System.models` introspection — enumeration of all model classes (Bus, Line, GENROU, etc.) with their `idx` lists | `core/wrapper.topology_snapshot()` to build the topology summary | Topology endpoint missing or duplicating elements |
| 2 | `Fault`, `Toggle`, `Alter` model param shapes — kwargs accepted by `ss.add('Fault', ...)`, `ss.add('Toggle', ...)`, `ss.add('Alter', ...)` | `core/disturbance.py` translates substrate `DisturbanceDef` payloads to these kwargs | `DisturbanceDef` schema breaks on disturbance creation |
| 3 | `TDS.callpert` per-step hook — assigning a callable runs it once per integration step | `core/wrapper.run_tds()` and `core/stream.py` for streaming + abort polling | TDS streaming silently degrades or hangs |
| 4 | `dae.ts` time-series structure — `dae.ts.x`, `dae.ts.y`, `dae.ts.t` arrays grow during TDS | `core/tds_steps.py` reads a step back from these when an event has written over the arrays (contract 13); `core/wrapper/pmu.py` reads the PMU histories from them | Streaming returns wrong column shape or no data |
| 5 | `andes.load(path, addfile=..., setup=False)` semantics — load without committing setup so disturbances can be added | `core/wrapper.load_case()` and `reload_case()` | `add_disturbance` always raises post-setup; v0.1 disturbance flow broken |
| 6 | **`PFlow.run()` and `TDS.run()` require an explicit prior `ss.setup()` call.** Verified empirically against ANDES 2.0.0: `PFlow.run` on a non-setup System raises `IndexError` because `dae` has no allocated address space. ANDES does NOT auto-call setup from these routines. The wrapper calls `ss.setup()` first if `not ss.is_setup`. | `core/wrapper.run_pflow()`, `run_tds()` | If a future ANDES version starts auto-calling setup, the wrapper's explicit `ss.setup()` call becomes a no-op-with-warning and we must handle that case rather than treating "second setup returned False" as a failure. |
| 7 | `sys.audit("open", ...)` event coverage — Python-level open() calls from ANDES are visible to the audit hook | `core/wrapper` --strict-fs best-effort logging of secondary file reads | --strict-fs misses reads (caveat already documented in the trust model — C-extension reads are not caught even today) |
| 8 | **Power-flow settings live on the System, not in `config`, once it is built.** `PFlow.config.tol`, `max_iter`, `method`, `n_factorize` and `linesearch` and `Bus.config.flat_start` are read while the solver runs. `method` is one of `NR`, `dishonest` and `NK` (`PFlow.config._alt`): `run()` lowercases it to choose the solver, and `nr_solve` compares it with `"dishonest"` as it is on every iteration, refactorising the Jacobian while `niter < n_factorize`; `linesearch` (0 or 1) is read once, at the start of `nr_solve`, which then keeps the point it steps back from with `np.empty_like`. `NK` calls SciPy's `newton_krylov` through `PFlow.newton_krylov()`, which `run()` calls with its default `verbose=True`, so SciPy prints a line per iteration to standard output whatever the log level; it stops by SciPy's own rule and reads none of `tol`, `max_iter` and `linesearch`, and it leaves `niter` at 0 and `mis` at `[1]`. A failed `NK` run raises out of `run()` instead of returning False: SciPy's `NoConvergence` is not caught, and after the `ValueError` that is, `run()` reads `mis[-2]` and raises `IndexError`. `PV.config.pv2pq` is not read while the solver runs: the `PV` and `Slack` models copy it into their `qlim` `SortedLimiter` (`enable`) when they are constructed, so writing the config of a loaded System does nothing. The limiter's own `enable` is the live switch, and its flags (`zl`, `zu`, `zi`, `ql`, `qu`, `nql`, `nqu`) stay where a run leaves them, `check_var` returning early once it is off. State estimation is run the same way: `SE.run(measurements=..., algorithm=...)` reads `SE.config.tol` and `max_iter` when it starts, takes `andes.se.algorithms.wls` or `lav` (iteratively reweighted least squares in NumPy, no LP solver) as `algorithm`, returns `False` when `max_iter` runs out rather than raising, writes no bus array (the estimate is `SE.result["x_est"]`), and adds the angle-reference pseudo-measurement in `SE.init`; `SE.chi_squared_test(confidence)` returns `(passed, J, threshold, dof)` with `dof = nm - 2 * Bus.n` after a `wls` run, and `(False, J, inf, 0)` after any other; `Measurements.generate_from_pflow(seed=...)` draws its noise from its own `numpy.random.default_rng(seed)`. Verified against ANDES 2.0.0. | `core/pflow_options.pflow_options_applied()`, used by `core/wrapper.run_pflow()`, which also keeps `NK`'s printing off standard output, answers its two exceptions as a run that did not converge, and reads its mismatch off `dae.f` and `dae.g`; `core/wrapper/se.SeMixin.run_se()` | A renamed or relocated limiter attribute makes `enforce_q_limits` silently do nothing (the integration tests in `tests/integration/test_pflow_options.py` fail), and a flag the limiter stops resetting would carry one run's generator limits into the next. A solver setting that is no longer read at `run()` time is reported in `settings` without taking effect: the same file holds that each reaches the branch of the solver it selects (the line search counted through `np.empty_like`, the dishonest method by its iterations against NR's on Kundur's system, `NK` by reaching NR's solution with `niter` 0). A failed `NK` run that starts returning False needs nothing from the wrapper; one that raises something else reaches the client as a server error, and `test_newton_krylov_that_does_not_converge_says_so` fails. A changed SE signature or test result breaks the `algorithm`, `tol`, `max_iter`, `noise_seed` and `chi_squared` of `POST /sessions/{id}/se` (`tests/integration/test_se_algorithms_andes.py` fails). |
| 9 | **ANDES names and places its time-domain variables itself, and drops some of them.** `dae.x_name` and `dae.y_name` hold `"<variable> <Model> <idx>"` (the model name is not repeated when a string idx already has it, and underscores in the idx become spaces) and are filled by `System.set_dae_names` only when `TDS.init()` runs; before that they are empty or hold the power-flow variables. A static device that an online dynamic model replaces (an `IdxParam` with `replaces=True`) loses its algebraic variables in `DAECompactor.compact_dae()` during `TDS.init()`; its `var.a` then points at other variables. Verified against ANDES 2.0.0. | `core/dae_vars.dae_variables()` lists the names from `System.find_models`, each model's `states`, `algebs`, `idx` and `idx_params[...].replaces`, with no setup; `core/stream._DaeReader` reads `dae.x` / `dae.y` at the position `dae.x_name` / `dae.y_name` give each name, which is the only address that is right after compaction | A changed name format or a changed rule for what is compacted makes a name the catalogue offers unreadable: its stream column is `nan` and the worker logs that it is not in `dae.x_name` or `dae.y_name`. `tests/integration/test_dae_vars.py` compares the catalogue with `dae.x_name` / `dae.y_name` of three bundled cases and one with a machine out of service, and every column with the model's own array at every step of a faulted run. |
| 10 | **ANDES reports through the standard `andes` logger and installs no handler of its own.** Every ANDES module logs to `logging.getLogger(__name__)`, so its records reach the `andes` logger. | 11 | **A continuation run is steered and read through three private methods of the CPF routine and the live attributes of the reactive limiters.** `CPF._bus_vmag()` is called once for every point the routine keeps, and once more for a last point it refines (a full curve's return to `lambda = 0`), each time right after `CPF._corrector(lam, xy_prev, lam_prev, step, z, dfg)` returned `(success, niter, lam)` for it. `CPF._dfg_dlam(lam)` gives the derivative of the equations with respect to lambda at the current state. The routine evaluates the limiters with `niter=0, err=1.0`, so the `qlim` `SortedLimiter` of `PV` and `Slack` switches a generator during CPF only when its `min_iter` is 0 (a live attribute, copied from `PV.config.min_iter` at construction): with the default of 2, ANDES's documented "`pv2pq` also applies during CPF" keeps the generators the power flow held and switches no other. The limiter latches: a generator it holds is never let go, also where its voltage comes back across the set-point. A float `stop_at` shortens the step that would cross it and refines the crossing point with lambda held, ending the run; a target the curve does not cross on the way up is not one it stops for, and the run turns at the nose and follows the lower branch past `lambda = 0` until the corrector fails, and a target of 0 is crossed only on the way back, as `FULL`. `natural` fixes lambda in the corrector, so the routine finds its nose only by failed steps and ends a `FULL` run with "Corrector failed" at the nose. ## Upgrade procedure

1. Bump the version range in `pyproject.toml` deliberately (never automatic).
2. Re-run the curl walkthrough (`pytest -m acceptance`) on a fresh venv with the new ANDES.
3. For each row in "The fourteen API contracts," verify the contract still holds. Add a row to the verification matrix.
4. If any contract changes, update the wrapper before bumping the production pin and add a regression test in `tests/integration/`.
